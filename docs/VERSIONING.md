# VT7Pty Versioning Policy

Status: implemented for Roadmap Step 0.5. Updated: 2026-09-22.

VT7Pty keeps separate identities for its package, public API, internal
client-agent protocol, and exact source. One number cannot describe all four
without making compatibility ambiguous.

## Current identities

| Identity | Current value | Authoritative source |
| --- | --- | --- |
| Package | `0.5.0-dev` | `VERSION.txt` |
| Public C API | `1.0` | `src/include/vt7pty_version.h` |
| Client-agent protocol | `1` | `src/shared/Protocol.h` |
| Source | Git commit and dirty state | generated by the build |

Build scripts read these sources rather than maintaining duplicate version
values. Agent diagnostics, verification JSON, package manifests, archive names,
and Windows version resources derive from them.

## Package version

VT7Pty uses `MAJOR.MINOR.PATCH` for published versions and a clear development
suffix between releases. The 0.5.x line is pre-stable: no general source, API,
ABI, or protocol compatibility is promised unless release notes explicitly say
otherwise. `0.5.0` will be published only after Milestone 0 acceptance and a
separate release review.

Advancing the package version records project evolution. It does not alone
prove compatibility or milestone completion.

## Public API and ABI

The public C surface uses `vt7pty_*` functions and types and `VT7PTY_*`
constants and macros. VT7Pty ships no WinPTY compatibility aliases. This is an
intentional source and binary compatibility break and does not imply
compatibility with WinPTY or ConPTY.

`VT7PTY_API_VERSION_MAJOR` and `VT7PTY_API_VERSION_MINOR` provide the readable
API version. `VT7PTY_API_VERSION` encodes the major component in the upper 16
bits and the minor component in the lower 16 bits. API version 1.0 identifies
the renamed inherited surface; it is not a stability promise for the 0.5.x
line. Milestone 2 will finish the VT7-facing ownership, concurrency,
cancellation, structure-versioning, and lifetime contract.

## Client-agent protocol

The DLL and agent communicate across a process boundary and must never pair
silently when their protocol is incompatible. Protocol version 1 adds an
explicit `VT7Pty-Agent` identity and numeric version before ordinary setup
data. The DLL rejects missing, malformed, wrong-identity, older, and newer
agents with public, actionable error codes and messages.

Protocol versions advance only for incompatible wire changes. Package patch
versions do not automatically advance the protocol. Release notes record the
package-to-protocol mapping.

## Windows file versions

The numeric Windows file and product version for `0.5.0-dev` is `0.5.0.0`.
The string file and product versions retain the full `0.5.0-dev` value. Every
maintained binary receives consistent VT7Pty product metadata, its own original
filename, the prerelease flag, and source-generated identity.

The fourth numeric component remains zero throughout this development version.
A different reproducible build-component rule requires an explicit policy
change before a published release uses it.

## Source and artifact identity

Every test package and diagnostic report identifies package, API, protocol,
source commit, dirty state, architecture, configuration, toolchain, SDK, and
artifact hashes. A locally rebuilt artifact is not an issued package merely
because its source version string matches.

## Upstream history

Keep WinPTY tags, copyright notices, Git authorship, the preserved README, and
[RELEASES.md](../RELEASES.md) intact. VT7Pty changes belong in
[CHANGELOG.md](../CHANGELOG.md). Future upstream imports record their exact
source revision and resulting VT7Pty version without rewriting history.
