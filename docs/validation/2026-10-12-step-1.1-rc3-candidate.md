## Extension and oracles

The [runner guide](../FIDELITY_BASELINE.md) specifies the recipes and deadlines.
Version 3 has 37 entries: 25 workflow observations, independent state/child and
portable JSON oracle suites, and ten negative controls. It adds nine child cases
across CMD, installed Windows PowerShell and pinned PowerShell 7.2.24:

- Processed Ctrl+C handled exactly once, final output, deliberate native exit 37.
- Default-handler Ctrl+C termination with native status 0xC000013A.
- Unprocessed Ctrl+C and z as ordered key records, no control event, Ctrl released.

Each compares actual mode/handler/keys, independently owned process exit status,
the shell's reported exit code, return to the prompt and a file-backed next
command barrier. The test authenticates the private pipe peer and validates
its direct parent and executable image before adopting cleanup ownership.
Default-handler termination has no final packet or output-marker requirement;
that distinction is recorded explicitly.

Two cooked-read probes observe a pending ReadConsoleW call after the fixture
echoes PROBE_TYPED. One sends VT byte 0x03 through VT7Pty; the other invokes
GenerateConsoleCtrlEvent directly inside the owned fixture. Handler delivery
and read completion are separate observations. A later boundary Enter records
retained text as recovery evidence, never as successful cancellation. The
reader's buffer stays alive until its owned thread has joined. Successful
fixture completion drains the stream through EOF.

Two added negative controls inject duplicate child-control count and wrong
native exit status into the oracle input. Raw native observations remain intact.
Independent unit cases cover wrong event types, modifiers, repeat/extra keys
and malformed/bounded child packets.

## Diagnosis and next evidence

The retained processed-input path at
[src/agent/ConsoleInput.cc](../../src/agent/ConsoleInput.cc) calls
GenerateConsoleCtrlEvent for byte 0x03. Its inherited comment describes a cooked
ReadConsole limitation and references
[WinPTY issue 116](https://github.com/rprichard/winpty/issues/116).
Microsoft documents
[control-handler signal delivery](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent)
and [cooked ReadConsole behavior](https://learn.microsoft.com/en-us/windows/console/readconsole)
as distinct mechanisms.

The two native probes support that explanation independently of shell or editor
behavior on WOLF. Combined with the version 1 Windows 7 prompt failures, this
made cooked-read cancellation the leading Step 1.2 investigation. The returned
[three-tier target review](2026-10-12-step-1.1-rc3-windows7-baseline.md) now confirms
the same probe behavior on NESSY, TURTLE and LEOPARD. All applicable active-child
cases pass. The matching real-shell failure mechanism remains an inference from
these observations; shell internals have not been instrumented.
No cancellation mechanism has been changed or accepted by this candidate.

NESSY and TURTLE each report 31 Pass / 6 Fail; LEOPARD reports 26 Pass /
6 Fail / 5 NotApplicable. Both oracles and all fault controls pass with zero
harness errors, and all native/aggregate metadata matches. A/B observe all
37 entries; C executes 32, with five PowerShell 7 cases NotApplicable.
LEOPARD successfully runs the portable JSON oracle under PowerShell 2.0 without
KB3191566 or a machine upgrade.

Seven broader coverage groups remain NotRun. Step 1.1 is still open. A later
input fix must cancel cooked typed text without executing it, return a usable
fresh prompt, and retain the proven active-child, processed/unprocessed and
PowerShell 7 behaviors.
