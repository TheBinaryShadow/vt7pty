## The same three failures in every repetition

Each 33-case input cohort passes the other 30 cases and fails exactly these
three. The raw signatures are identical on all three machines.

| escape-live-replies | Ten navigation records, then z | The escape sequences arrive as literal escape/text records, then z |

The timeout recipe requests a 1,200 ms gap between successive byte chunks.
The UTF-8 character disappears; lowercase z survives. This case does not
service cursor replies during those gaps. Its later recorded reply is serviced
after the chunk loop, so its presence is not evidence of live interleaving.

The live UTF-8 case records one ESC[1;1R cursor-position response. The č is lost,
and the literal bracket/coordinate suffix reaches the application. The euro,
supplementary UTF-16 pair and final uppercase Z remain intact.

The live escape case records ten cursor-position replies. Instead of the eleven
required significant key-down records, it has 35 significant records containing
the literal ESC[D, ESC[C and other encoded navigation text. I retain the original
Unicode units, virtual keys, modifier records, writes and reply bytes. The raw
audit combines surrogate pairs only for its readable text comparison.

These are measured failures, not intentional fault controls or successful
qualification. The completed input controllers correctly return exit 1.
There is no additional Ctrl+C or Ctrl+Break event in these failing captures.
