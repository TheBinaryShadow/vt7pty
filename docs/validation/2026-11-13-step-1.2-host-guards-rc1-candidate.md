## Corrections retained during development

I kept the preliminary runs and their original outcomes:

- The first controller failed admission before the suite because the previous
  research agent only admitted its version-4 controller. A distinct guard agent
  now admits the exact version-5 controller; the reference stays unchanged.
- The first full matrix passed 27/34 cases. Six PowerShell child launches lacked
  the invocation operator for a quoted executable path. The remaining CMD public
  case received one event but left its cooked read pending, reproducing the known
  public-route limitation.
- I corrected the launch syntax and aligned the public child guard with the
  established event/normal-exit contract. The host child route still requires
  an aborted cooked read and an intact second read. The stronger failed public
  read observation is preserved, rather than reclassified as a pass.

The [preliminary evidence](results/step-1.2/host-guards-rc1/preliminary/child-contract/native/suite/cases.json)
and its source snapshot explain that boundary. The
[reviewer controls](results/step-1.2/host-guards-rc1/controls/reviewer/controls.json)
reject premature rundown, an upgraded receipt, fake kernel denial, duplicate
child events, a foreign fence key and the wrong PowerShell 7 engine. The
[admission controls](results/step-1.2/host-guards-rc1/controls/integrity/controls.json)
also reject changed inner packages when their outer file hashes are updated.
