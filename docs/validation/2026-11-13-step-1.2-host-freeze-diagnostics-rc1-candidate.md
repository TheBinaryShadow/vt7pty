## What the traces establish locally

The [independent review](results/step-1.2/host-freeze-diagnostics-rc1/audit/evidence-review.json)
verifies 3,677 returned evidence-file hashes, portable/native aggregates and
original outcomes. All three original controls also pass the strict H3 reviewer.
The experiments record 750 host messages and 23,388 agent events, with no recorded
coverage gaps or operational issues.

All 33 focused phases observed their declared condition and retained their lease
through the deadline observation. Cancellation met the original deadline in all
24 selection-free or unsynchronized delay phases and failed in all nine held
selection phases. No scrape/resize freeze, expiry or peer loss occurred inside
the held intervals. Ordinary work continued in all six delay controls, and
output and queued resize checks passed after release. Actual pre-send intervals
were 66.900 to 90.785 ms for the declared 50 ms delay; I do not treat them as equal.

On WOLF, selection remained 7 through each selected deadline and became 0 after
the agent's normal Escape. The agent still cached frozen state at release.
Each selected pending read stayed pending, then recovery Enter returned the
original H3_FOCUSED_PENDING line with no control event. This local run does not
demonstrate the suspected Windows 7 sequence where C clears selection and a
later Escape clears the read's text. The target traces must settle that question.
