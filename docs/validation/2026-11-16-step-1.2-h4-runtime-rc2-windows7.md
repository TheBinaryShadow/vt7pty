## TURTLE's interrupted cohort

The third runtime cohort starts at 00:53:00.732 on November 16, Zagreb time.
Thirty-four cases directly report:

Host cancellation requires the ordinary caller desktop: Windows error 13

The [startup guard](../../src/shared/BackingDesktop.h) compares the caller's
desktop with OpenInputDesktop before creating the private backing desktop.
That comparison failed. The probe still identifies the caller desktop as
Default, but it does not record the other desktop's name.

I confirmed that TURTLE locked or changed desktops during the run. This fits
the observed refusal. It does not turn the run into a pass or establish which
desktop was active from the trace alone. There are no host-ready or cancellation
result records in this failed cohort; it is a startup-precondition failure.

The remaining failures follow that blocked startup: the race aggregate has no
valid contenders, and three lifetime actors report broken pipes before returning
their retained process identities. Those three also record owned-cleanup false.
I do not treat their default host-exit flags as proof of observed host cleanup.

Three denial cases are marked passed. The missing/wrong-helper records show
the same earlier desktop refusal, so they do not establish helper validation
in this cohort. I will make desktop preconditions and denial causes explicit
in a future harness pass. The strict bundle gate already rejects the cohort.

TURTLE also retains one failure in the unchanged original control:
powershell-empty reaches a fresh prompt and continues, but records no fixture
control event. Cleanup, host exit and hook removal pass for that case. I keep
it separate from the new runtime result and do not infer that the desktop
change caused this original-control miss.
