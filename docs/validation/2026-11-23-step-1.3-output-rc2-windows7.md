## Unicode text and placement

I found two repeatable column differences. The snapshots preserved the
requested text, and the reader reconstructed those same code points. The
table shows the column of the bar following each sample, starting at zero.

| Sample | Windows 7 native cell | Windows 7 reconstructed cell | WOLF native and reconstructed cells |
| --- | ---: | ---: | --- |
| e plus U+0301 | 4 | 3 | 4 and 3 |
| U+4E2D | 3 | 4 | 4 and 4 |
| U+1F642 | 4 | 4 | 4 and 3, with U+FFFD in the native snapshot |

On all three targets, the backing console used Lucida Console and output
page 852 for these Unicode writes. It stored the combining mark in its own
cell and U+4E2D in one cell. The test reader attaches the mark to the base
character and gives U+4E2D two cells. The captured stream sends each sample
and its bar contiguously and restores the cursor later. The cursor ends at
the native position in both cases. The bar positions differ under the
reader's declared width rules.

Windows 7 retained the surrogate pair D83D DE42 for U+1F642. Both runtimes
emitted its original UTF-8 and placed the bar at the native column. WOLF's
console had already stored U+FFFD in the source cells when the runtime read
them.

## Code pages and screen operations

I confirmed that each target applied pages 437, 1250 and 65001 before its
byte write. The valid CP65001 write returned a count of 6 for an 11-byte
request and produced the complete expected text. For malformed CP65001,
Windows 7 stored U+FFFD at the invalid byte. Both runtimes reproduced that
text with valid UTF-8. WOLF omitted the invalid byte in its native snapshot.

The positioned colors, partial erase, right-edge wrap and clipped scroll
matched in all 24 observations of those operations. The raw VT request
returned Win32 error 87 on every target run. Output mode stayed at 3 after
the request for 7, so the fixture recorded the capability as unavailable
and skipped the dependent write.

## Step 1.3 status

I marked the three-tier characterization complete. The width differences
occur in both pinned runtimes under the same test reader. The remaining
Step 1.3 work is to determine how far the VT stream can preserve native cell
placement when the backing console and consumer use different width rules.
