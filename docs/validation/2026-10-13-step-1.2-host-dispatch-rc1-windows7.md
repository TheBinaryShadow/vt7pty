## Discovery and actual callback execution

Across all 54 host observations, fixture self-query, controller child-query and
agent query agree: NTSTATUS 0, eight returned bytes, low two bits zero.
Each host is native x64 System32 conhost.exe, with matching user/logon/integrity/
session checks and medium integrity. Each controlled console contains exactly
its agent and fixture. Creation identities and retained handles bind lifetimes.

As in H1, each initial snapshot exposes two GUI-capable host threads and
the console HWND externally reports the agent PID. H2 identifies a specific
host-owned thread in both title-change observation windows, then verifies its
actual execution inside the host through the callback and independently checked
pipe peer PID. Inside every callback, the window owner and window thread match
the executing host and discovered thread. This distinguishes host execution
from the out-of-context event callback running in the controller.

## Protocol, input isolation and lifecycle

The nine repetitions check 225 exchanges: 126 accepted responses, 90 expected
rejections and nine receipt-only outcomes. Every response retains the expected
nonce, execution identity and accepted sequence. Rejections do not advance
that sequence.

The negative cases reject duplicate, wrong-nonce, cross-session, stale-host-
generation, expired, schema/size, sequence-gap and rebind requests. Replacement
session C rejects retired A's nonce; valid requests after rejections still work.
Concurrent B retains its original pending line across all neighboring sessions.

Each repetition separately confirms:

- A received request without a final acknowledgment disables dispatch and
  refuses retry/fallback; ordinary input still completes afterward.
- An exited host is rejected before another write.
- A separate controller exits with code 73 without explicit unhook/C++ cleanup;
  its verified owned clients and observed host exit while neighboring B survives.
- Live channels retire, installed hooks are removed, owned clients are cleaned
  and all six retained host handles signal. No host is terminated.

All 45 reads return exactly ALPHA, BRAVO_KEEP, CHARLIE, DELTA or ECHO plus CRLF,
with successful read status and error zero; each raw stream contains its
controlled text. These are ordinary Enter-completed reads. F deliberately exits
with its read pending. No cancellation or control event is requested.

The channel verifies a controlled same-user endpoint and binds each request to
its session. This is not a security proof against compromised code under that
user, nor qualification of untested hosts, desktops, access policies or load.

## What I concluded and what comes next

I accepted H2 for NESSY, TURTLE and LEOPARD. The
[staged design](../HOST_CANCELLATION_DESIGN.md) advances to H3: a test-only
cooked-read cancellation prototype using the verified host context. It must
discard the old line, produce appropriate read completion and exactly one
control event, preserve the next read and restore real CMD/native PowerShell
prompts without executing canceled text. Failure, concurrency and existing
child/raw-input/PowerShell 7 guards remain required.

H4 then qualifies production integration and regression behavior. No production
mechanism is selected by this H2 acceptance. The runtime remains the released
0.5.0 pair; no runtime source, package or version change is made in this review.
The broader fidelity corpus was not rerun, F01 remains unresolved, and
CancellationImplemented and MilestoneAccepted remain false. Step 1.2, broader
Step 1.1 coverage and Milestone 1 remain open.
