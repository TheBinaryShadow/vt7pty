## Accepted environment disposition

The Non-ESU record reports machine name `NESSY`, manufacturer `VMware, Inc.`,
and model `VMware20,1`. That model normally identifies a virtualized guest and
therefore does not independently satisfy the project's ordinary physical-host
wording. On 2026-09-23, the project owner explicitly directed that `NESSY` be
treated as a full-fledged physical machine for Step 0.6 acceptance.

This owner-approved disposition is recorded rather than silently describing
the VMware-reported environment as native hardware. It applies to this Step
0.6 result. Later milestone and release gates continue to use the documented
environment requirement unless another explicit scope decision changes it.

## Decision

Step 0.6 is accepted. The retained implementation uses the approved C++20
toolchain without its obsolete compatibility layers, builds cleanly under
`/W4 /WX`, passes repeatable Release static analysis, retains source-level
debugging, and preserves the tested backend behavior on the development host
and both accepted Windows 7 tiers. No third-party dependency or broad console
algorithm rewrite was introduced.

Diagnostics and security-boundary modernization proceeds in Step 0.7.
