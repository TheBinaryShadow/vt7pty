# Lifecycle rc4 on Windows 7

Reviewed on 2026-11-27 in Europe/Zagreb.

I matched all three runs to the issued rc4 ZIP and verified 759 evidence
files. All 60 positive cases and 30 session contract checks passed. The
six missing-marker controls behaved as expected. LEOPARD ran on installed
PowerShell 2.0 without KB3191566.
[Candidate identity](2026-11-27-step-1.5-lifecycle-rc4-candidate.md)

## Resize RPCs

I measured 64 calls per runtime on each machine. The table shows the
nearest-rank p95 and peak in milliseconds. The diagnostic agent traced
192 calls and recorded 5,193 spans with zero drops.

| Machine | 0.5.0 p95 / peak | Screen rc3 p95 / peak | Diagnostic p95 / peak |
| --- | ---: | ---: | ---: |
| NESSY | 16.629 / 33.462 | 15.321 / 18.085 | 11.577 / 13.815 |
| TURTLE | 2.116 / 2.641 | 1.985 / 2.059 | 2.044 / 2.332 |
| LEOPARD | 19.915 / 23.008 | 15.273 / 18.980 | 14.601 / 28.595 |

I used 20 ms to inspect the long calls. The 0.5.0 control crossed that
threshold once on NESSY and three times on LEOPARD. The pinned screen rc3
control stayed below 20 ms on both, after p95s of 36.08 ms and 38.48 ms in
lifecycle rc3. The NESSY outlier came from the untraced 0.5.0 control.
The test-reader resize peaked at 0.797 ms across the suite.

## LEOPARD trace

Both traced calls over 20 ms came at the end of trial 4. The agent began
handling each request within 0.10 ms. I compared the sequence that clears
selection, changes the screen buffer size and re-enters selection to the
median of the other 31 calls in the same direction.

| Call | RPC (ms) | Agent resize (ms) | Buffer resize and selection (ms) | Same-direction median for that sequence (ms) |
| --- | ---: | ---: | ---: | ---: |
| 15, grow to 100×30 | 26.63 | 26.40 | 13.74 | 5.07 |
| 16, shrink to 80×25 | 28.60 | 25.51 | 12.85 | 5.62 |

Re-entering selection took 8.03 ms during growth. Clearing selection
took 4.13 ms during shrink, and the buffer-size call took 5.56 ms. The
shrink also spent 2.99 ms from the start of the reply to caller return.
I can place most of the delay inside the agent resize. The trace
measures elapsed time at these call boundaries, so the source of the
wait inside Windows remains open.

## Resources and Step 1.5 status

All 216 process intervals showed cycle activity. CPU time stayed flat
in 191 of them. In the pinned controls, median active agent cycles per
operation rose by about 1% on NESSY and LEOPARD and fell by 10% on TURTLE.
Individual TURTLE pairs ranged from 28% fewer cycles to 18% more.

I qualify the resize collection and the tested F08 cases with session
flags 0. I keep Step 1.5 open for the intermittent resize tail,
performance budgets and the remaining process cleanup checks.
