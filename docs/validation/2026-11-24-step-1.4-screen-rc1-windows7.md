## Restoration and resize

Both original controls passed on all three machines. The primary marker was
present after explicit restoration and after application exit. Across all
30 shell workflows, CMD and Windows PowerShell reported exit code 37,
executed the edited command and showed the fresh prompt.

The 12 live resize workflows matched all 96 child viewport and buffer
measurements. The app kept drawing, processed the edit and reached the
expected frame. In all 12 cases the child exited between the checks
surrounding the final resize, and the shell returned at 100×30 with the
primary marker intact. The synchronized resize and both live resize
scenarios pass on Windows 7. I retain their WOLF differences in the
[development-host record](2026-11-24-step-1.4-screen-rc1-candidate.md#wolf-results).

## Cursor visibility

All six differences came from the alternate checkpoint in
`SCREEN_CMD_EXPLICIT`. The native snapshot had a hidden cursor at (7, 23),
and the last visibility command in the captured VT bytes was `CSI ?25 h`,
which shows it. The cell text, attributes, cursor position and dimensions
matched. The primary screen and CMD return matched after restoration.

The agent opens the active buffer with `CONOUT$` in these sessions. The
scraper reads cells and geometry from that buffer and queries cursor
visibility from standard output. A buffer switch leaves the standard
output handle bound to its original buffer. I will query visibility using
the buffer the scraper is reading, then verify it against the same
restoration and resize controls.
