## Recipes and development observations

The [investigation](../INPUT_CANCELLATION.md) records the contract and mechanism
dispositions; the [runner guide](../FIDELITY_BASELINE.md) specifies execution.
Version 4 retains all 37 prior entries and adds two MechanismProbe cases:

- READCONSOLE_RECORD_EVENT writes C down/up, character 0x03 and Ctrl modifier,
  then generates one Ctrl+C event. API success alone does not qualify cancellation.
- READCONSOLE_OWNED_CANCEL targets the fixture's exact pending ReadConsoleW thread,
  then generates one event. It checks the canceled call and a subsequent read
  against NEXT_PROBE plus CRLF. It never enumerates real application readers.

Input records succeed and one Ctrl+C event arrives, but the read remains pending.
After boundary Enter, it returns PROBE_TYPED, character 0x03 and CRLF.

Direct cancellation succeeds: the first ReadConsoleW returns BOOL TRUE, error 995
and zero text, with exactly one control event. However, the second read stays
pending after NEXT_PROBE and Enter. A second Enter recovers only CRLF. The new
line was lost, so the overall probe remains Fail. First-call success cannot
stand in for recovery of the console's read state.

Both cases drain the final fixture marker, preserve exit 37 and clean their
owned processes. The portable runner records MechanismFailures separately,
includes probe infrastructure/cleanup failures in harness health and returns
exit 1 for these actual failed observations. MilestoneAccepted remains false.

The existing Windows 7 Unicode/resize passes are not overturned by WOLF's
separate development mismatches. No Windows 7 result is inferred from this run.

records 31 Pass / 8 Fail on NESSY and TURTLE, and 26 Pass / 8 Fail /

CancelSynchronousIo returns FALSE with error 1168 while the read remains pending.

from WOLF's successful first-call cancellation and lost next line.
Both measured API approaches are rejected for the target corpus.

The independent target review verifies 106 native/aggregate observations,

## Windows 7 run procedure and next decision

Extract the entire archive into a fresh local directory on each target and run:

- RUN-FIDELITY-NONESU.cmd on NESSY.
- RUN-FIDELITY-ESU.cmd on TURTLE.
- RUN-FIDELITY-LEGACY.cmd on LEOPARD.

Use the installed PowerShell 2.0 runner on the legacy tier. The default A/B
PowerShell 7 path remains C:\Program Files\PowerShell\7\pwsh.exe. Return each
complete results subdirectory to K:\VT7_work\results. Preserve Fail statuses
and API error values; these are mechanism measurements, not a fixed runtime.

The failed target approaches now inform a separate user-mode cancellation
design. The next recommended work investigates one owned console host's actual
identity and a cancellation request/acknowledgment path, with failure and
isolation tests. An application-read shim remains a distinct design alternative.
A production fix must pass actual prompt cases and the existing interruption
guards under a distinct runtime identity. Step 1.1's broader coverage and
Step 1.2 remain open; this short candidate does not replace release soak qualification.
