## Local validation

`Package-VT7Pty.ps1 -Configuration Release` completed a clean Release rebuild,
MSVC native static-analysis rebuild, 29/29 passing local Release tests,
archive extraction, and every per-file manifest check. The verification
record inspected 20 maintained binaries and 19 DLL exports. The DLL, agent,
and debug server report string file/product version `0.5.0`. The tests ZIP
manifest identifies the source commit above, `0.5.0`, and a clean tree.

The exact extracted tests ZIP ran in fast mode under Windows PowerShell 5.1
on the Windows 10 development host. All 29 fast cases passed, including
the timeout negative control and diagnostic bundle; the 120-minute soak was
`NotRun`. The runner correctly returned `Fail` because this was not a Windows 7
SP1 target and the required soak was intentionally omitted. This is a
package-integrity smoke check, not target acceptance.

A separate attempt to run the same smoke check under the development host's
PowerShell 2.0 engine stopped before tests: its
`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe.Config` contains
an unrecognized configuration section for .NET 2.0. The engine itself starts,
but `System.Web.Extensions` cannot parse the JSON manifest on that host.
This host-specific failure does not qualify or disqualify the legacy target.
The unchanged target-side runner previously passed on `LEOPARD` for rc7;
`LEOPARD` must now run this exact `0.5.0` package.

## Required target acceptance

On each machine, copy the same `-tests.zip` and matching `.sha256` file
from the handoff folder, verify the test ZIP SHA-256 above, and extract
the ZIP to a new local directory. From an ordinary Command Prompt there:

- `NESSY` (non-ESU): `RUN-WINDOWS7-ACCEPTANCE.cmd NonESU`
- `TURTLE` (ESU): `RUN-WINDOWS7-ACCEPTANCE.cmd ESU`
- `LEOPARD` (PowerShell 2.0, without KB3191566):
  `RUN-WINDOWS7-LEGACY-ACCEPTANCE.cmd`

Allow the complete 120-minute soak on each machine. Return the complete
`results` directory from each run, including JSON, text, diagnostic streams,
and bundles. Follow the [acceptance procedure](../WINDOWS7_ACCEPTANCE.md).
The three machine records must identify this source commit, `0.5.0`, and the
test-manifest hash above; all 30 cases must pass.

After their return, run `tools/release/Review-VT7PtyRelease.ps1` against
this release-set manifest and the three JSON records, inspect environment
and diagnostic evidence, and record the decision. The
[release notes](../releases/0.5.0.md) are prepared. No `v0.5.0` tag or
GitHub Release exists yet.
