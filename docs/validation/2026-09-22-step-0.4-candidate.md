## Platform implementation

The candidate makes Windows 7 SP1 x64 the single active platform floor:

- `_WIN32_WINNT`, `WINVER`, and `NTDDI_VERSION` are fixed at Windows 7 and the
  PE subsystem minimum is `6.01`;
- every maintained DLL and executable embeds compatibility declarations for
  Windows 7, 8, 8.1, and 10/11;
- the XP/Vista background-desktop implementation, helper-agent command,
  spawn-protocol field, debug controls, project membership, and public
  `WINPTY_FLAG_ALLOW_CURPROC_DESKTOP_CREATION` flag are removed;
- named pipes directly use `PIPE_REJECT_REMOTE_CLIENTS` and
  `GetNamedPipeClientProcessId`, both within the supported floor;
- console-font selection uses `CONSOLE_FONT_INFOEX`,
  `GetCurrentConsoleFontEx`, and `SetCurrentConsoleFontEx` with the retained
  Windows 7, Windows 8, and modern-console font tables;
- runtime version detection uses `RtlGetVersion`; x86/WOW64 diagnostic paths
  and deprecated compatibility checks are gone; and
- later-Windows console behavior remains selected by the Windows 8-or-greater
  branch and the existing modern Windows 10 console detection.

## Dependency audit

The verifier inspected all 16 maintained PE images. Every image is x64,
declares subsystem `6.01`, has an empty delay-import directory, contains all
four compatibility GUIDs, and matches its exact approved DLL dependency set.
It also rejected a maintained list of direct APIs introduced after Windows 7.
The complete `dumpbin /headers /imports` output and extracted manifest for
each binary are under ignored `artifacts/verification/x64/<Configuration>`.

The remaining dynamic lookups are deliberate and Windows 7-safe:

- `SystemFunction036` (`RtlGenRandom`) is resolved from `advapi32.dll`, with
  the inherited CryptoAPI fallback;
- `RtlGetVersion` is resolved from the already-loaded `ntdll.dll`; and
- file-version functions are resolved from the explicit System32 copy of
  `version.dll`, preventing working-directory DLL substitution.

No other `LoadLibrary`, `GetProcAddress`, or delay-load path remains in the
active runtime.

## Development-host results

Both Debug and Release passed the maintained verification command. Each run:

- produced all required DLL, executable, library, and PDB artifacts;
- ran the string-builder unit test and inherited client-agent lifecycle test;
- resized sessions and launched real Command Prompt and Windows PowerShell
  children through the public API;
- checked agent version and exact source commit;
- checked deterministic argument quoting and bounded output;
- verified the inherited DLL export surface; and
- verified architecture, subsystem, imports, delay imports, manifests,
  version resources, PDBs, hashes, and source identity.

The build continues to report the known inherited `StringBuilder.h` C4244
conversion warning in the three runtime projects. Warning cleanup belongs to
Step 0.6 and does not change this platform result.
