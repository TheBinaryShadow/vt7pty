## Findings and limits

The host's normal key-processing path cancels the pending read and delivers
the event together. In these runs, ReadConsoleW returns TRUE with error 995
and empty text; the following read returns the expected line. Each measured
handler sees exactly one event. CMD and native PowerShell regain fresh prompts,
do not execute the canceled command, and execute the next command successfully.

The prototype runs on private desktops that are never displayed. The root
independently locates each console HWND on its retained desktop; the callback
also reports the exact desktop. The neighboring session uses a different
desktop and keeps its input throughout the suite. Every observed host exits.
A job containing only the created test shell ensures abrupt fixture death
does not leave that shell behind.

I retained the
[preliminary failures](results/step-1.2/host-cancellation-rc1/preliminary):
cross-desktop thread queries were denied, an early raw reader stopped at a
modifier record, and a normal-exit pipe race caused a controller failure.
Independent review later found that a requested C-down state bit was absent
from the observed table. I removed that unnecessary change and now verify
the exact modifier-only table before delivery. These exploratory records are
not candidate acceptance evidence.

H3 remains open for the three Windows 7 runs, true completion/close races,
actual OS-denied installation behavior, the handled/default active-child shell
matrix and PowerShell 7.2.24 with PSReadLine. Private-desktop results do not
qualify ordinary-desktop production use or GUI applications. H4, F01, Step 1.2
and Milestone 1 remain open.

The [preservation inventory](results/step-1.2/host-cancellation-rc1/preserved-files.json)
records 1,253 byte-for-byte copies plus the inventory itself. It includes final
precommit evidence, H1/H2 regressions, preliminary failures, exact-package
records and review controls. Build binaries are excluded from the repository;
the immutable ZIP carries the executable artifacts.
