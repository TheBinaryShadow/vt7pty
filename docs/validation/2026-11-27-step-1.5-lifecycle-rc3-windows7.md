## Cycle measurements

I verified all four trial pairs per machine and 7,998 completed operations
in the active resource windows. Every one of the 144 idle and active
process intervals showed cycle activity, including 127 where CPU time
stayed flat.

The table gives the median active agent cycles per completed operation
and the nearest-rank p95 resize RPC. Each cell goes from 0.5.0 to screen
rc3. I compare the cycle counts within each machine.

| Machine | Agent cycles per operation (millions) | Resize RPC p95 (ms) |
| --- | ---: | ---: |
| NESSY | 3.59 → 3.40 | 14.99 → 36.08 |
| TURTLE | 0.56 → 0.50 | 2.00 → 2.13 |
| LEOPARD | 3.60 → 3.49 | 16.02 → 38.48 |

Individual active agent pairs ranged from 34% fewer cycles per operation
to 21% more. TURTLE's caller used more idle cycles per second in all four
pairs, with its median rising from 0.67 to 0.81 million. I have usable
cycle reference measurements on all three tiers. I need repeated runs to
set budgets that account for the variation between trials.

## Resize timing

On NESSY, screen rc3 exceeded the machine's rc2 peak on 12 of 16 calls
in pair 3. On LEOPARD, it exceeded the rc2 peak on 21 of 32 calls across
pairs 3 and 4. Both growth and shrink calls were affected. Peak RPC
times were 45.70 ms on NESSY and 64.64 ms on LEOPARD. The maximum
test-reader resize was 0.62 ms across the suite.

The longer calls warrant a focused RPC timing trace. I measure active
cycles in a separate window from the latency samples.
