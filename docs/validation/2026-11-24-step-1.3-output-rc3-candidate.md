## What the captures show

The scraper supplies rows of native cells to Terminal::sendLine. The
emitter interprets the native attributes and surrogate pairs to read code
points, appends their UTF-8 bytes, and keeps a separate count of native
cells. The emitted text run leaves character widths to the receiving
renderer. A later cursor command can restore the cursor after a preceding
character landed in a different column.
[Emitter source](../../src/agent/Terminal.cc) ·
[Microsoft cursor positioning](https://learn.microsoft.com/en-us/windows/console/console-virtual-terminal-sequences#cursor-positioning)

I inserted a Cursor Horizontal Absolute command immediately before the
bar in a replay of each retained sample. I also replayed the original
bytes with a test policy that assigns just U+0301 and U+4E2D one cell each.
The table uses zero-based columns and describes all six paired copies of
each Windows 7 sample.

| Sample | Native bar | Original replay | Replay with the cursor move | One-cell replay |
| --- | ---: | ---: | --- | --- |
| e plus U+0301 | 4 | 3 | Bar at 4, with the accent attached to e and a blank cell before the bar | Native row and cursor match |
| U+4E2D | 3 | 4 | Bar at 3, with the ideograph erased when the bar hits its second cell | Native row and cursor match |

On WOLF the unmodified stream and the reference reader already place the
CJK bar at column 4. Giving that ideograph one cell moves the bar to
column 3. This demonstrates the dependence on the reader's width rules.
I use the replay to measure text and placement independently. The Unicode
width guidance calls for tailoring character widths to the rendering
environment. The inherited console notes also record differences with
font, font size and code page.
[Unicode East Asian Width](https://www.unicode.org/reports/tr11/) ·
[WinPTY console font notes](../historical/ConsoleFontNotes.txt)
