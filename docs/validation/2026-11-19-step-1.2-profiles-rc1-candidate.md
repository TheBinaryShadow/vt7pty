## Extraction-path blocker

All four profile cases fail during runtime startup at the new rc1 extraction
path. Each trace records Install owned-thread host callback: Windows error 126.
The same candidate files pass at the previously registered path. Source,
product hashes and API/protocol identities match in both locations.

This matches the earlier H4 path-dependent session problem. I suspect the same
session-scoped hook-module registration issue; this contrast alone does not
prove its underlying cause. I have kept the runtime unchanged. A fresh WOLF
sign-in will let me rerun the exact archive's five automated phases, both
synthetic manual workflows, the combined reviewer and its 13 altered-bundle
controls. Those checks remain pending. I have not counted the registered-path
contrast as a passing exact-path qualification.

## Preliminary findings and limits

I retain the failed development iterations. They exposed a fixture insert-mode
mismatch, incomplete metadata collection when launched from a PowerShell 7
parent, file-publication races and synthetic key coalescing when scan codes
were missing. The final harness corrects those issues. Target launchers use
x64 Windows PowerShell and restore the caller's original process-policy
variable before starting test shells.

Early Windows PowerShell smoke runs reported SaveIncrementally. Those runs may
have added test commands to WOLF's normal history. I corrected the smoke setup
to use an explicit private history path before the first ReadLine and left the
personal history file in place. Diagnostic stream captures came from explicitly
marked synthetic -NoProfile runs after that correction. Ordinary-shell output
capture remains disabled.

The actual ordinary-profile phase still needs physical input on all three
Windows 7 machines. It records profile file hashes, editor identity/settings,
policy scopes, fixed-result booleans and nonprinting key counts. It keeps
personal shell output in the live display. The bounded frontend does not
qualify wider output reconstruction or arbitrary terminal features.

The public Ctrl+Break transport gap and the recorded Escape/reply framing
limits remain unchanged. I have not accepted Step 1.2, Milestone 1 or VT7 integration.
