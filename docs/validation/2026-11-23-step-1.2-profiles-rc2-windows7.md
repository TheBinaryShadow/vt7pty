I verified the 24 completed workflows against 150 command proofs, including

bindings and resize. The native children each recorded one Ctrl+C and exited
with status 37. The six clean PowerShell 7 cases also meet their profile recipes.

NESSY and TURTLE each reported three passing profile trials. The independent
review rejects those trials because:

- All 12 Windows PowerShell 5.1 fixtures record one initial error. The
  snapshots give the count, so the error itself still needs identification.
- All six layered PowerShell 7 cases use Emacs mode and pass the F6 binding
  check, but PSReadLine refuses history prediction on the backing console.
  The snapshots record PredictionSource None. PSReadLine 2.1.0 explicitly
  rejects prediction on its legacy Win32 console path.
  [Version 2.1.0 source](https://github.com/PowerShell/PSReadLine/blob/v2.1.0/PSReadLine/Options.cs#L133-L140)

LEOPARD runs under Windows PowerShell 2.0 and CLR 2.0. Its six fixture shells
start and reach the first snapshot. The snapshot's JavaScriptSerializer
throws on a circular reference involving PSMethod, and each snapshot file is
empty. The command checks never start. The collector itself completes and
the same machine passes both frozen control phases without KB3191566.

## Ordinary profiles

| Machine | Returned manual runs | Result |
| --- | --- | --- |
| NESSY | Two runs, both engines each time | All four attempts reach F8, then fail waiting for snapshot-0.json (Win32 2). |
| TURTLE | Two runs, both engines each time | All four attempts stop while sizing the display buffer (Win32 87), before F8. |
| LEOPARD | One run | The automated prerequisite blocks the manual phase before shell launch. |

On NESSY the runner produces no startup snapshot, so I cannot tell whether
the helper definition, its invocation or its result write failed. The manual
runner records only startup and cleanup metadata in these returned folders.

On TURTLE the runner requests a 160 by 60 buffer before adjusting its window.
Windows gives the new buffer the current window dimensions and rejects a buffer
smaller than that window. The initial dimensions were not recorded, so this
explains a possible source of the invalid parameter and needs a measured check.
[Screen buffer creation](https://learn.microsoft.com/en-us/windows/console/createconsolescreenbuffer)
and [size limits](https://learn.microsoft.com/en-us/windows/console/setconsolescreenbuffersize).

The eight manual attempts record zero completed checkpoints. The six early
legacy automated failures and eight aborted manual launches report a fixture
exit-status error. Their retained process records confirm owned cleanup and
backing-host exit. The manual files contain no shell transcript, profile
contents or history contents.

qualify on Windows 7.
