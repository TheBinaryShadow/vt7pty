## What this establishes

The selected title-event thread belongs to the independently identified host.
A thread-scoped WH_CALLWNDPROC callback then executes inside that host for a
bounded WM_NULL notification to the owned console window. The controller's pipe
client PID independently matches the callback's process identity.

On WOLF, the external HWND query reports the agent, while the same query inside
the callback reports the real host PID and dispatch thread. All current
greetings and responses retain that distinction. Both peer identities, process
creation times, the owned parent chain and the common console-host association
are checked before a session can bind.

The fixed protocol rejects duplicate, forged-nonce, cross-session, stale-host,
expired, schema/size, sequence-gap and rebind requests. A replacement session
rejects the retired session's nonce. Valid requests still succeed after rejection.

Missing final acknowledgment is treated as OutcomeUnknown after an observed
receipt: dispatch is disabled, retry is refused and no fallback event is sent.
A host that already exited is rejected before another write. Explicit Close
retires a live channel; abrupt controller death separately requires its clients
and host to exit. The probe never terminates a host.

The callback uses nonblocking pipe I/O and no worker thread. Completed synchronous
notifications establish return from those invocations; hook removal by itself
is not a drain claim. Retained host handles must signal before acceptance.
The channel is a controlled same-user endpoint, not a security boundary against
a compromised process under that user.
