## Accepted evidence deviation

Both supplied records expose the same `TURTLE` computer name, hardware, OS
identity, and hotfix inventory. Those recorded fields cannot independently
prove that the runs came from different physical systems or different update
states. The project owner explicitly directed that the ESU and Non-ESU records
be treated as results from two different machines for now and accepted as the
two required Step 0.5 tiers. This temporary evidence treatment is recorded
rather than inferred from the machine metadata.

Future milestone and release acceptance retains the documented requirement to
use the intended physical tiers unless another explicit scope decision changes
that requirement.

## Decision

Step 0.5 is accepted. The active repository and package use VT7Pty artifact,
project, source, header, API, constant, diagnostic, environment-variable,
endpoint, test, and package identities without WinPTY compatibility aliases.
Package `0.5.0-dev`, API `1.0`, protocol `1`, and source identity are explicit.
The DLL rejects missing or incompatible agents rather than silently pairing
with them, and the exact candidate passed the accepted development-host and
physical Windows 7 procedures.

Native code modernization proceeds in Step 0.6.
