## Changes and contract

I preserve a valid unfinished UTF-8 scalar across idle periods. Strict prefix
validation rejects invalid leads, continuations, overlong forms, surrogates and
out-of-range values without consuming following valid input. The escape timeout
no longer clears the byte queue. After one timeout scan, I wait for new input
instead of repeatedly scanning and tracing the same unfinished character.

I filter a solicited cursor-position reply before it reaches key decoding.
The reply can span pipe reads and can arrive between bytes of an unfinished
UTF-8 or escape token. Receiving it does not finish the token, refresh its input
timer or start a repeated-query loop. Rejected prefixes are replayed in order;
prefix storage is bounded, and unsolicited/duplicate reports follow normal
key decoding.

The [input guide](../INPUT_FIDELITY.md#input-and-reply-contract) defines the
required reply serialization and timeout behavior. A standalone Escape now
uses the one-second fallback rather than the old reply fence. That delay and
the cursor-report/modified-F3 ambiguity remain explicit input API work before
Milestone 2 freezes a contract. I make no interactive latency claim here.

The product diff is limited to ConsoleInput.cc, ConsoleInput.h,
CursorReportFilter.h and UnicodeEncoding.h. The public headers, protocol,
H4 runtime cases, focused qualification cases and H4 golden case inventory
remain unchanged from the accepted H4 parent. The changed runtime still needs
its own Windows 7 qualification; earlier H4 acceptance is not a pass for rc2.
