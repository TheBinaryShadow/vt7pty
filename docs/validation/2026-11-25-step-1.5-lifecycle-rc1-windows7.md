# Lifecycle rc1 on Windows 7

Reviewed on 2026-11-25 in Europe/Zagreb.

I matched the NESSY, TURTLE and LEOPARD runs to the issued ZIP and verified
387 evidence files. Each machine passed all 14 positive cases, detected both
missing-marker controls and passed all 10 session contract checks. LEOPARD
ran on installed PowerShell 2.0 without KB3191566.
[Candidate identity](2026-11-24-step-1.5-lifecycle-rc1-candidate.md)

## Drain, close and recovery

I checked all 200 rows and the final marker in each of the 12 CMD and
Windows PowerShell drain runs. The child exited with code 37 before the
reader started. The stream drained to EOF and the agent exited.

Every failed launch returned the expected missing-executable error and
allowed a working command in the same session. Closing the selected
session left its neighbor usable and able to drain. The rc3 runtime
also passed repeated close and rejected resize after retirement. The
existing gates covered 3,000 create and close cycles and 600 resize
requests across both runtimes.

## Timing and resources

I used the nearest-rank 95th percentile from 48 samples per runtime on
each machine. Each cell gives released 0.5.0 and screen rc3 timings in ms.

| LEOPARD | 17.24 → 18.91 | 11.10 → 15.53 | 38.06 → 38.32 |

NESSY's shrink phase accounted for the largest increase. Its p95 rose
from 9.57 ms to 24.02 ms. The p95 of the sum of the three measured phases
rose from 55.65 ms to 62.41 ms on NESSY and changed by at most 0.28 ms
on the other two machines. The resize timer includes the RPC and the
test reader's resize. The runner measured 0.5.0 first on each machine.

The caller held five more handles with screen rc3 and its maximum
sampled private memory was 136 to 156 KiB higher. Handle counts stayed
flat within every trial, and both runtimes passed the post-warm-up
handle gate on all three machines. I measured zero CPU time deltas in
107 of 108 sampled process intervals. I need longer idle and active
windows to derive a CPU budget.
