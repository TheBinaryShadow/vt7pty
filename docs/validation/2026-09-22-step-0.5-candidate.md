- runtime artifacts are `VT7Pty.dll`, `VT7Pty-Agent.exe`, and
  `VT7Pty-DebugServer.exe`;
- public headers, 19 exported C functions and types, constants, project/source
  paths, tests, diagnostics, agent lookup, package metadata, and PDBs use the
  VT7Pty identity;
- active environment variables are `VT7PTY_DEBUG` and
  `VT7PTY_SHOW_CONSOLE`;
- control, data, and debug named-pipe endpoints use VT7Pty names with explicit
  version markers;
- no WinPTY header, binary, exported-symbol, environment-variable, or endpoint

- remaining WinPTY references are attribution, provenance, migration,

`0.5.0-dev` string file/product versions. Their numeric Windows version is

## Compatibility enforcement

The setup packet now begins with the exact `VT7Pty-Agent` identity and protocol
version `1`. The DLL validates both fields before accepting data-pipe names.
`VT7PTY_ERROR_AGENT_EXE_MISSING` identifies a missing colocated agent, while
`VT7PTY_ERROR_AGENT_INCOMPATIBLE` identifies missing/malformed handshake data,
a wrong identity, or an older/newer protocol.

The verifier exercised each path through the actual DLL using isolated output
directories and the purpose-built incompatible-agent fixture. The standalone
protocol test also covered valid, missing, malformed, wrong-identity, older,
and newer handshakes.
