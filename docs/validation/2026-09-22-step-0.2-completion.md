## Maintained project boundary

`VT7Pty.sln` contains 14 projects: the client DLL, agent, native debug server,
two inherited tests, seven controlled console fixtures, and two console-mode
tools. The new fixture and tool projects share one imported MSBuild definition
and produce x64 Debug and Release executables with linked PDBs.

The seven fixtures moved to `tests/fixtures` cover command-line arguments,
console input records, UTF-16 output, two input/echo paths, screen-buffer
output, and escaped console output. The input and output mode inspectors moved
to `tools/console`. Other experimental, destructive, or specialized `misc`
programs remain for individual classification in Step 0.3.

Modern compiler errors exposed by the move were corrected in fixture/tool code.
The corrections include explicit checked integer conversions, current CRT input
functions, validated text conversion, matching ANSI command-line access, and a
fix to the inherited `\uXXXX` decoder's bit shifts. No backend source or public
API changed.

## Limits and next boundary

Interactive fixtures were compiled and inspected but were not treated as
unattended tests without controlled console state. Their focused drivers belong
to the permanent test system in Step 0.8. Linked PDB bytes remain
non-deterministic between clean rebuilds, as already recorded during the
transition; their presence, association, and source-line function are verified.

No physical Windows 7 claim is made here. Non-ESU and ESU physical acceptance
remains required after platform cleanup and for milestone and release
candidates. Step 0.3 can now remove superseded build systems and Unix-derived
components while preserving this clean native boundary as regression evidence.
