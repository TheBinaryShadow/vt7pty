## Development validation

Both configurations built with /W4, warnings as errors and static analysis.
Precommit Debug and Release verification each passed all 30 local checks.
The source commit was then rebuilt and its clean Release verification again
passed 30 checks before packaging. The precommit records explicitly retain
their dirty state and parent revision; they are not exact-candidate records.

The ZIP was independently extracted and its portable runner executed on WOLF:
run developmenthost-20261013-090858-6d713bb8, Windows 10 IoT Enterprise LTSC
10.0.19044, installed Windows PowerShell 5.1. All three repetitions passed.

Each repetition established six consistent host observations and returned the
three expected ordinary input lines. Across all repetitions, the independent
review checks 18 identity observations, nine read results, three native/aggregate
matches and 44 copied run files byte-for-byte. All three sessions per repetition
cleaned up, and all observed hosts exited after their clients closed.

The observed query values have low bit 0 set. The stored raw values, flags and
normalized PIDs agree across fixture self-query, controller child-query and
agent query. The HWND reports the agent as owner; the independently identified
System32 conhost.exe is different. User/logon/integrity/session checks pass.
Multiple host threads report GUI state: no dispatch thread is inferred from that.

An independently extracted altered copy, with README.md changed, is rejected
by package integrity verification before any native test or results directory
is created. The original issued ZIP is unchanged.

The [evidence index](results/step-1.2/host-identity-rc1/README.md) links full records.

## Target handoff and next gate

Run the appropriate RUN-HOST-IDENTITY-NONESU.cmd, RUN-HOST-IDENTITY-ESU.cmd or
RUN-HOST-IDENTITY-LEGACY.cmd from a fresh local extraction. Use the ordinary
test account; do not elevate to bypass a failed identity check. PowerShell 7
is not used. LEOPARD remains the PowerShell 2.0/no-KB3191566 acceptance tier.
Return the complete results folder.

H1 success is conditional identity evidence for controlled sessions. It is
neither a security proof against a malicious client nor a cancellation fix.
The next dispatch experiment requires actual host/thread execution evidence,
an authenticated session-bound request/acknowledgment contract, lifecycle and
failure handling. H2/H3/H4, F01, Step 1.2 and Milestone 1 remain open.
