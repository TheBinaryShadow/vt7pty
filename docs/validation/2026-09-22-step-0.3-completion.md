## Implemented removal groups

The cleanup was kept in three reviewable commits, with the complete verifier
run after each group:

1. `7894142` removed the Unix adapter, GYP, GNU Make, Python 2 shipping,
   AppVeyor, `vcbuild.bat`, generated-file batch helpers, obsolete shell build
   wrappers, and the temporary baseline harness whose evidence was already
   preserved.
2. `cc17ac7` classified every `misc` item. It moved native probes to
   `tests/manual`, utilities to `tools/console`, and research to
   `docs/historical`; removed duplicate or obsolete Unix/Python experiments;
   and added native bounded-output and console-color fixtures.
3. `59ea495` removed retained compiler shims and stale source conventions. It
   replaced the custom mutex with `std::mutex`, the old formatting layer with
   C++ runtime formatting, compiler-specific `noexcept` and move workarounds
   with C++20 language facilities, and private SDK fallbacks with current SDK
   declarations. It renamed `UnixCtrlChars.h` to `ControlCharacters.h`, moved
   test-only helpers out of runtime source, and enabled `/Zc:preprocessor`.

The component inventory records the final disposition of inherited material.
Historical upstream documentation and release notes intentionally retain names
of old systems. A source audit found no active build or source include,
conditional, script, or project dependency on the removed technology. The few
remaining Cygwin references in agent comments describe observable application
behavior that the native backend still handles; they do not select a build or
implementation path.

## Limits and next boundary

This step deliberately retains XP/Vista runtime branches and inherited names;
their removal belongs to Steps 0.4 and 0.5 respectively. It also leaves
interactive and destructive manual probes unautomated until the permanent test
system in Step 0.8 can provide controlled console state, timeouts, and cleanup.

No physical Windows 7 claim is made here. Step 0.4 must simplify the runtime to
its Windows 7+ platform floor and then validate the resulting candidate on the
defined physical machines.
