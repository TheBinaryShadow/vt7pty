## Host and isolation observations

Across all 54 identity observations, fixture self-query, controller child-query
and agent query agree. Every query returns successful NTSTATUS 0 and eight
bytes. The low two bits are zero on these Windows 7 targets; the raw value
therefore equals the normalized PID. WOLF's separate development observations
have bit 0 set. The existing masking rule handles both measured representations.

Each identified host is native x64 System32 conhost.exe, distinct from the
agent and fixture, with matching user/logon/integrity/session checks.
The console contains exactly the controlled agent and fixture. The console
HWND reports the agent PID, not the independently identified host PID.

All 54 thread snapshots contain two distinct, host-owned threads for which
GetGUIThreadInfo succeeds. Neither result identifies the actual dispatch thread.
DispatchThreadVerified remains false in every observation and aggregate.

Each repetition establishes distinct simultaneous A/B hosts with pending
cooked reads. A completes normally and closes; replacement C starts and
completes while B remains pending. Repeated observations retain B's host and
fixture identity. B finally returns its original BRAVO_KEEP line intact.
The 27 read results contain exactly ALPHA, BRAVO_KEEP or CHARLIE plus CRLF,
with successful read status and error zero. Closed A is ineligible for dispatch.

These are ordinary Enter-completed reads. No cancellation, hook installation,
host message, remote memory write or selected dispatch thread is involved.
H1 establishes controlled-session consistency and isolation; it is not a
security proof against a malicious client or a promise about untested systems.

## Disposition and next gate

H1 is complete for NESSY, TURTLE and LEOPARD. The
[staged design](../HOST_CANCELLATION_DESIGN.md) now advances to H2: establish
the actual host dispatch context and a bounded, authenticated session-bound
request/acknowledgment path. Reject stale, duplicate and cross-session requests;
measure lifecycle and failure behavior before attempting cancellation.

H3 must then prove that cancellation discards the old line, delivers the
appropriate single event, preserves the next read and restores real shell
prompts. H4 adds production integration and regression qualification.

The released runtime is unchanged. This research package does not rerun the
wider fidelity corpus, fix F01 or qualify a new release. CancellationImplemented
and MilestoneAccepted remain false. Step 1.2, broader Step 1.1 coverage and
Milestone 1 remain open.
